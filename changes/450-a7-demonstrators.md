### Changes

- **The first wiki pages, written in French and in English, and the environment variable reference** (4.5.0). Five pages of `wiki/` are `ready`, each written natively in both languages and found by `search_docs`:
  - "Restore the Studio on a fresh installation" / « Exercice de restauration sur une installation vierge »: the hosted Studio's restore drill, step by step. It gives the restore time measured on the 4.2.3 reference deployment (28.7 s, then 59.7 s), with its date, volume and conditions, the guarantee that a restore into a database already holding a project is refused, and the test that proves it. It also says what a restore can lose (the RPO) and why going back after a migration means restoring an older backup into a new add-on. The page says plainly that it was not replayed on a live installation.
  - "Write refused on the hosted Studio: span locked (423)" and "… stale base revision (409)": the exact message, the causes (a lease another member holds for 120 s, renewed while their Studio stays open; an owner's exclusive lease; a file saved after you read it), how to tell them apart, and what to do (wait, ask, an owner's audited takeover, apply your edit on the latest version).
  - "Bridge and connector troubleshooting": what the Reality Bridge's 409 and 503 mean, a signal sent twice, a connector down. A search for "409" without a context now shows the Studio's page and the Bridge's, each naming its service.
  - "Environment variables": every variable quest-n-click reads (93, from the Studio Server's secrets to the test scripts' switches) and the ones Clever Cloud and its add-ons inject, each with its own section, its origin, whether it is a secret and can come from a `_FILE`, and the files that read it.
- **The environment variable register** (4.5.0). `wiki/data/env.json` describes each variable in French and in English. `npm run wiki -- env` regenerates the reference page and its identifiers from the register and from the code: `process.env`, `import.meta.env`, the Python tools and the shell scripts of `ops/` and `clevercloud/`. `npm run wiki -- check` fails on a variable the code reads without a description, on a described one the code no longer reads, and on a computed read (`process.env[name]`) nobody resolved.

### Fixed

- **`search_docs` no longer reads the word "studio" as the variable `STUDIO`** (4.5.0). An identifier written in capitals (an environment variable such as `STUDIO`, `PATH` or `PORT`) now counts only when the query holds it exactly; before, any question with the word "studio" ranked the environment variable page high. A search for `STUDIO_SESSION_KEY` now shows that whole name in its excerpt, not `STUDIO`, and an excerpt no longer doubles the page's own bold.
- **`read_doc {id}` from an installed package now says where the page lives online** (4.5.0). Its structured content gives `url.versioned`, the page's permalink on Pages for that very version and doc revision (`/docs/<version>/r<n>/<lang>/<id>.html#<section>`), and `url.current`, the wiki's page, labelled as the current documentation rather than this version's. The plan asked for both; the package only gave the version and the commits.
