## 4.2.3 PR 6: the game in Git (H5, D44)

- `studio-server/src/server/git.ts` (`GitSync`): a clone in `workDir/git`, fetched each time; a push writes the head's
  files in `path` (removing what the head no longer has there), one commit of the revisions since `git_pushed` with a
  line per operation and a `Co-authored-by` per author, then `git push origin HEAD:refs/heads/<branch>`, never forced;
  refused (409) when the branch moved since `git_commit` or exists unseen; nothing new, nothing pushed. An import checks
  out the branch or a commit, writes the game as it is there in one operation under the exclusive lease (5,000 files,
  64 MiB at most), and records the commit when it is the branch's tip. Git's environment: PATH, HOME in the work folder,
  no prompt, no system or user configuration, the deploy key in a 0600 file for one command.
- Config `git` (remote without credentials, branch, path, committer) and the secret `STUDIO_GIT_KEY`; routes GET
  `/api/git` (a reviewer), POST `/api/git/push` and `/api/git/import` (an owner); the Play tab's Git panel
  (`src/studio/git-panel.ts`); the exclusive lease helper shared with prepare (`main.ts`).
- Limits: one repository per instance; an import of a commit that is not the branch's tip is written but a push then
  waits for the branch to be imported; a file outside `path` is never touched; LFS and submodules are not read.
- Docs: STUDIO-SERVER "The game in Git" (en, fr); the threat model's row.
- Tests: `tests/studio-git.test.ts` (a bare repository: a push with two authors, nothing new, a second push on the
  first, a file removed; a moved branch refused and left as it was; an import as one revision then a push on it, the
  rest of the repository kept; a bad ref, an unknown branch, a commit without the game; the routes),
  `tests/dom/studio-git-panel.test.ts`.
