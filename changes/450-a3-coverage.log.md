## 4.5.0, A3: the anchor inventory, the coverage matrix, the legacy order and the freeze

- **The inventory.** `wiki -- coverage --init` reads 70 pages: the 32 files of `docs/en` and of `docs/fr`, `PRODUCTION.template.md` included, and the six root pages. It finds 1,036 sections, 1,034 anchors, 246 code blocks and 1,879 limit candidates.
  - Headings of every level outside fenced code, with GitHub's slug: lowercase; punctuation, emoji and symbols removed; accents kept; each space a `-`; `-1`, `-2`… for a repeated heading. Two READMEs also have text before their first heading, kept as a row of its own.
  - Explicit `<a id>` / `<a name>` anchors (none in `docs/` today).
  - Each code block's sha256, language and line.
  - The figures `quality:baseline` writes into the READMEs (`<!-- metric:… -->`) are masked before hashing. Otherwise every pull request that adds a test would move a frozen section.
  - The limit candidates come from markers (*only*, *not*, *never*, *cannot*, *uniquement*, *seulement*, *pas encore*, *jamais*, *ne … pas*, *limite*, *attention*, *warning*), looked for outside inline code. *ne … que*, the French "only", was added. They are a review aid.
- **The cross-check.** It found 10 anchored links into these pages in the tracked files (READMEs, BENCH's own links, a comment). All resolve. Markdown links are read relative to their file with A2's link scanner, so never inside code. Paths written in code or in other files are read from the root; GitHub `blob/main` URLs are read too. The matrix, `legacy.json` and the manifest's `replaces` are not scanned: they hold every anchor by construction.
- **The matrix**, `wiki/coverage.json` (`quest-n-click-docs-coverage` v1), has one row per section. Each row gives the old file, heading, level, anchor, line range, hash, code blocks, explicit anchors and limit candidates (`pending`, `reported`, `not-a-limit`). Then come the fields a person fills: `destinations` (`id` or `id#section`), `decision`, `reason`, `examples`, `verification`, `planned`, `migrated`.
  - All 1,036 rows are planned from Annex A, the French twins section by section like their English page: 725 keep, 197 rewrite (split across several pages), 114 drop. Every drop is a shipped milestone of `ROADMAP.md` in both languages, with its reason: the CHANGELOG and the LOG hold them, and `start.roadmap` keeps what is ahead.
  - Section ids are proposed in kebab case where the destination is obvious. Every row of the eight `read_doc` pages has one, so the legacy order rebuilds sections rather than whole pages.
  - 172 of the 213 manifest pages now have `replaces`. Their schema accepts the root pages and GitHub's accented anchors.
- **The merge.** `wiki -- coverage` keeps what a person wrote. A new section comes in flagged `added`. A section whose text changed is flagged `changed` and is no longer `migrated`. A section that left its page stays at the end, flagged `removed`. A limit keeps its status while its sentence is unchanged. `--init` refuses to replace a matrix without `--force`. The JSON is written in a stable layout. The manifest is written by hand, so its `replaces` are set in place: every other byte is kept, and the result is checked by parsing it back.
- **`wiki/legacy.json`.** For each of the eight `read_doc` names (`DOCS`, imported from `tools/studio/tools.ts`), it holds the ordered, deduplicated destinations of the old sections. It is generated by `wiki -- coverage`, and the check refuses one that drifted.
- **The check and the freeze.**
  - `wiki -- check` now checks the matrix: schema; destinations are manifest pages, and on a written page an existing section; a planned row has a decision and a destination; a drop has a reason; every code block of the pages is in a row; `legacy.json` and `replaces` are the matrix's.
  - A matrix out of step with `docs/` is an error that names `npm run wiki -- coverage`. `tests/wiki-coverage.test.ts` holds the same guard: `docs/` is frozen.
  - Rows without a decision are gaps. Flagged rows and unresolved incoming links are warnings.
  - `check`, `coverage` and `stats` print the two counters: planned 100 % for sections, code blocks and limit candidates; migrated 0 %.
- **Elsewhere.** `ci:plan`'s docs family also runs on the six root pages. A2's `mapLines` hands each fenced block to an optional callback; it and `mapLine` are exported, and nothing is duplicated.
