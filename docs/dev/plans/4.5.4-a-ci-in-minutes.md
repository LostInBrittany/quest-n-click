# 4.5.4 part A: CI in minutes – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a pull request that touches no product code (docs, wiki, workflows, release and wiki tools, tests) gets its CI in minutes, not 17–60.

**Architecture:** `tools/ci-plan.ts` already decides, per changed path, which heavy jobs run; `ci.yml`'s gated jobs read it and succeed with a notice when spared. This part adds one gate (`coverage`), narrows `windows`/`node-24` for the repository's own tools and the tests, lets the flaky `pwa-firefox` warn instead of failing `pr-gate`, and caps the candidate's mutation matrix so a PR is not queued behind it.

**Tech Stack:** TypeScript (tsx, Vitest), GitHub Actions YAML.

**Spec:** `docs/dev/PLAN-4.5.4-SIMPLE-RELEASE.md`, part A (and issue #302).

## Global Constraints

- Nothing tested at release time changes: `main`, a tag and the `full-ci` label still run `--all` (every gate, `coverage` included); the candidate runs everything.
- A spared job never has a job-level `if`: it runs one step that says `"<job> not needed by the plan"` and succeeds (the ruleset requires `coverage` and `node-24` by name).
- A path no rule knows still runs everything.
- The engine's, games', Bridge's and Studio's rules keep their gates (only `coverage` is added to them).
- Shell: absolute paths, never `cd <dir> && <cmd> <relative>`; tests run from the worktree with `npm --prefix <worktree> run -s test:node -- <files>`; never force-push; never bare `git stash`.
- Every branch adds `changes/<slug>.md` and `.log.md`; wiki changes in `wiki/en` and `wiki/fr` (French: no mid-sentence dashes), their pairs recorded `--kind ai --relation author`; `npm run wiki -- check` passes.
- English prose: the spaced en-dash ( – ), never the em-dash.

## Review Focus

1. A PR mixing a doc and an engine file: `coverage` must run (the union of gates).
2. A PR touching only `tests/fixtures/saves/`: `coverage` off is wrong there (it gates the upgrade path) – it stays on.
3. `main` push, tag, `full-ci`: `coverage` on (`--all`) and its ratchet `--strict` unchanged.
4. `pwa-firefox` red on a PR: `pr-gate` green with a warning naming it; any other job red still fails `pr-gate`.
5. A new top-level folder: still "everything" (the "knows every tracked file" test keeps passing).
